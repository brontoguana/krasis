Manager API

The browser uses this same versioned JSON API. Apply and Stop are asynchronous: retain the operation ID and poll it until terminal is true.

1. Read the owner token

Every POST requires the owner-only token; LAN mode requires it for every API request. On Linux/WSL:

TOKEN="$(tr -d '\r\n' < "${KRASIS_HOME:-$HOME/.krasis}/manager/token")"
BASE="__KRASIS_MANAGER_BASE__"
AUTH="X-Krasis-Manager-Token: $TOKEN"

On Windows PowerShell:

$Base = "__KRASIS_MANAGER_BASE__"
$Token = (Get-Content "$env:USERPROFILE\.krasis\manager\token" -Raw).Trim()
$Headers = @{ "X-Krasis-Manager-Token" = $Token }

2. Discover GPUs and installed models

curl -fsS -H "$AUTH" "$BASE/api/v1/gpus"
curl -fsS -H "$AUTH" "$BASE/api/v1/models"
curl -fsS -H "$AUTH" "$BASE/api/v1/status"

GPU identity is always the stable GPU-… UUID. A multi-GPU server appears on every GPU it owns with the same PID. Unrelated compute is shown as external and is never terminated.

3. Resolve measured choices, then validate

Ask the existing launcher for model-specific defaults and qualified attention/KV/topology choices:

curl -fsS -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"model_path":"/home/me/.krasis/models/org/model","gpu_uuids":["GPU-…"]}' \
  "$BASE/api/v1/configs/describe"

Take the returned config, change only required values, and validate it:

curl -fsS -H "$AUTH" -H 'Content-Type: application/json' \
  --data-binary @config.json "$BASE/api/v1/configs/validate"
Validation runs the normal launcher capability, topology, and computed-budget gates. It never stops a model. Deprecated AWQ/FP8 modes are absent; production experts remain INT4.

4. Apply to a GPU

GPU="GPU-…"
curl -fsS -H "$AUTH" -H 'Content-Type: application/json' \
  --data-binary @config.json "$BASE/api/v1/gpus/$GPU/apply"

HTTP 202 returns operation.id. The URL GPU must be in gpu_uuids. List every UUID for multi-GPU configurations.

5. Poll progress

OP="op-…"
while true; do
  JSON="$(curl -fsS -H "$AUTH" "$BASE/api/v1/operations/$OP")" || exit 1
  printf '%s\n' "$JSON"
  printf '%s' "$JSON" | grep -q '"terminal": true' && break
  sleep 2
done

States are queued, validating, stopping, waiting_for_gpu, launching, loading, then ready, stopped, or failed. The operation includes message, PID, port, GPU UUIDs, error, and bounded startup logs. Treat only ready as a successful Apply.

6. Stop a model

curl -fsS -X POST -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{}' "$BASE/api/v1/gpus/$GPU/stop"

Stop also returns HTTP 202. Poll until stopped or failed. Idle Stop succeeds as already idle. Any GPU in a verified multi-GPU assignment stops the one shared process.

Safety and errors

  • __KRASIS_MANAGER_NETWORK_DESCRIPTION__
  • Krasis does not change host firewall rules; LAN access may require allowing the selected port on the private network.
  • Apply validates before touching the current model.
  • Only a process proven to be python -m krasis.server can be stopped.
  • Unsupported modes, unrelated GPU owners, port collisions, cleanup timeouts, and startup failures remain explicit. There are no silent fallbacks.
  • A spawn is still loading; readiness requires an HTTP 200 health response.
